# ADR-001: Framework-Independent Domain Layer

## Status
**ACCEPTED** (Date: 2026-08-06)

## Context
The KVM1 Astrology Engine is designed to serve as an enterprise-grade calculation and interpretation platform for Vedic, KP, Jaimini, Nadi, Muhurtha, and AI-driven astrological systems.

Frameworks evolve rapidly. Web frameworks (such as FastAPI or Flask), validation libraries (such as Pydantic), and database ORMs (such as SQLAlchemy) introduce breaking API changes over time. Coupling core domain calculation models directly to external framework decorators, metaclasses, or base classes risks polluting domain logic with infrastructure concerns.

## Decision
We decide that **the Domain Layer (`domain/`) MUST remain 100% Framework Independent**.

1. **Pure Standard Library**: All domain entities, value objects, metadata, and calculation context envelopes MUST be implemented as pure Python dataclasses (`@dataclass(frozen=True)`).
2. **Zero Framework Imports**: No imports of FastAPI, Pydantic, SQLAlchemy, or third-party web/ORM libraries are allowed within the `domain/` directory.
3. **Immutability by Default**: Domain context objects are immutable (`frozen=True`) to prevent accidental state mutations across processing pipeline stages.
4. **Boundary Translation**: Validation rules or framework-specific DTOs (Data Transfer Objects) MUST reside in presentation or validation layers (`validators/`, `infrastructure/serialization/`, `routers/`), converting framework objects to/from pure domain entities at system boundaries.

## Consequences

### Positive
- **Long-Term Maintainability**: Core domain calculation logic and data models will never break due to third-party framework updates.
- **High Testability**: Pure Python domain models can be instantiated and unit-tested instantaneously without setting up application web contexts, database connections, or request mocks.
- **Portability & Reuse**: The domain models can be imported and executed seamlessly in CLI scripts, web apps, batch processing pipelines, or AWS Lambda / GCP Cloud Functions.

### Negative
- Require explicit DTO serialization/mapping layers when converting domain objects to JSON or OpenAPI schemas in API presentation controllers.
