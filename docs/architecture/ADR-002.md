# ADR-002: Dependency Injection & Core Interface Abstractions

## Status
**ACCEPTED** (Date: 2026-08-06)

## Context
The KVM1 Astrology Engine requires modular extensibility across multiple domains:
- Geocoding sources (Google Maps, OpenStreetMap Nominatim, GeoNames, Offline DB).
- Caching providers (In-Memory, Redis).
- Calculation Engines (Vedic, KP, Jaimini, Nadi, Muhurtha, Prasna, Panchapakshi).
- Rule Evaluation engines and audit logging providers.

Coupling high-level application orchestrators directly to concrete external service classes violates the **Dependency Inversion Principle (DIP)** and makes unit testing difficult without live external network endpoints.

## Decision
We decide to introduce **Core Interface Abstractions (`core/interfaces/`)** and a **Framework-Independent Dependency Injection Container (`infrastructure/container.py`)**.

1. **Abstract Interface Contracts**:
   - Every core service dependency (`IGeocoderProvider`, `ICacheProvider`, `ITimezoneService`, `IJulianDayService`, `ISwissephService`, `IAstrologyEngine`, `IRule`, `IRuleEngine`, `IAuditLogger`) MUST be declared as an Abstract Base Class (`ABC`).
2. **Pure Python DI Container**:
   - The application container (`Container`) is implemented in pure Python without external framework dependencies (such as `python-dependency-injector` or framework web extensions).
   - Supports singleton, factory, and mock instance override registrations.
3. **Decoupled Resolution**:
   - High-level application services depend strictly on interface types (`IGeocoderProvider`, etc.) rather than concrete adapter classes.

## Consequences

### Positive
- **High Testability**: External services can be mocked instantaneously in unit tests by registering dummy instances in `container.register_instance()`.
- **Extensiveness**: New engines, geocoders, or caching adapters can be plugged in without modifying existing calculation pipelines or API controllers.
- **Zero Overhead**: Minimal memory footprint and high execution speed with zero external library overhead.

### Negative
- Requires explicit registration of interface implementations during application startup in `main.py`.
