# ADR-005: Vedic Core Calculation Engine & Engine Registry

## Status
**ACCEPTED** (Date: 2026-08-06)

## Context
The KVM1 Astrology Engine needs to support multiple independent calculation systems (Vedic, KP, Jaimini, Nadi, Muhurtha, Prasna, Panchapakshi).

Calculating astronomical positions independently within each analysis module causes code duplication, performance degradation, and calculation drift.

## Decision
We decide to:
1. **Enforce Single Source of Truth**: Every calculation engine MUST read exclusively from `CalculationContext.astronomical_state` (computed once by `SwissephService`).
2. **Pluggable Engine Registry (`EngineRegistry`)**: System engines implement `IAstrologyEngine` (`engine_id`, `version`, `calculate(context)`) and register dynamically in `EngineRegistry`.
3. **Modular Sub-Engines**: `VedicEngine` orchestrates sub-engines:
   - `VedicPlanetEngine`: Placed `ChartPlanet` calculation.
   - `VedicHouseEngine`: House cusps and occupants.
   - `VedicHouseLordEngine`: Parashari sign ownership and house lord placements.
   - `VedicDrishtiEngine`: Graha Drishti aspects.
   - `VedicStrengthEngine`: Dignities, combustion, retrograde, and planet scores.

## Consequences

### Positive
- **Extensible Plugin System**: Future engines (KP, Jaimini, Nadi, Muhurtha) plug directly into `EngineRegistry` without modifying existing core code.
- **Single Source of Truth**: Ensures 100% astronomical consistency across all engines.
- **100% Backward Compatibility**: Calculation output structure matches existing API payload formats.
