# ADR-003: CalculationContext Lifecycle & Pipeline Orchestration

## Status
**ACCEPTED** (Date: 2026-08-06)

## Context
The KVM1 Astrology Engine requires a deterministic, highly auditable pipeline for astronomical calculation requests.

Past architectures suffered from:
- Services mutating global parameters or directly calling each other.
- Misaligned calculation contexts leading to state drift.
- Lack of execution lineage and stage performance visibility.

## Decision
We decide to adopt a **Single Envelope Pipeline Orchestration Pattern** governed by an immutable `CalculationContext`:

1. **Pure Orchestrator**: The `CalculationPipeline` is a pure execution coordinator. It contains **ZERO astronomical calculations** or business rules.
2. **Context Transformation Contract**: Each pipeline stage implements `IPipelineStage` (`process(context: CalculationContext) -> CalculationContext`). Services receive a `CalculationContext` and return a new enriched `CalculationContext` instance (`context.with_enrichment()`).
3. **No Direct Inter-Service Coupling**: Services must NEVER invoke each other directly; all communication occurs via attributes on the immutable `CalculationContext`.
4. **Single Source of Truth Astronomy**: `SwissephService` is the ONLY stage that invokes Swiss Ephemeris C-bindings. It produces the `AstronomicalState` once per request. Downstream analysis engines read exclusively from this state.
5. **Stage Performance & Audit Metrics**: Every pipeline stage attaches a `PipelineStageMetrics` record capturing runtime duration (`execution_time_ms`), `cache_hit` flags, context version transitions, and status.

## Consequences

### Positive
- **100% Deterministic & Auditable**: Every calculation step is logged with context version transitions and execution timing.
- **Single Source of Truth**: Eliminates planetary longitude recalculation errors in downstream engines.
- **Future Parallel / Async Readiness**: Clean `process(CalculationContext) -> CalculationContext` signature enables seamless async or distributed worker execution.

### Negative
- Requires passing context instances through stages rather than direct function calls.
