# ADR-007: Rule Engine Framework & Priority-Based Rule Evaluation

## Status
**ACCEPTED** (Date: 2026-08-06)

## Context
Astrological rules (Yogas, Arishta, Dignities, Raja Yogas) analyze planetary positions to form interpretations. Re-calculating planetary longitudes or house cusps inside individual rules causes severe performance degradation and calculation drift.

## Decision
We decide to implement:
1. **Rule Isolation Principle**: Rules MUST NOT calculate planets or houses. Rules read exclusively from `CalculationContext`, `AstronomicalState`, `VedicEngine` output, and `VargaRegistry` output.
2. **Standard Rule Taxonomy**: Every rule implements `IRule` and exposes: `rule_id`, `name`, `version`, `description`, `priority`, and `category`.
3. **Categories**:
   - `classical`, `yoga`, `raja_yoga`, `dhana_yoga`, `arishta`, `neecha_bhanga`, `functional_dignity`.
4. **Priority-Based Dispatch**: `RuleEngine` evaluates rules sorted in descending priority order (higher priority integer evaluated first) and returns structured `RuleResult` entities.

## Consequences

### Positive
- **Determinism & Performance**: Rules operate on pre-computed context, completing evaluations in microsecond timeframes.
- **Pluggable & Category-Scoped Execution**: Applications can execute all rules or evaluate specific categories on demand.
- **100% Backward Compatibility**: Public router APIs and astronomical calculation logic remain strictly intact.
