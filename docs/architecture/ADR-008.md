# ADR-008: Prediction Engine & Multilingual Presentation Reports

## Status
**ACCEPTED** (Date: 2026-08-06)

## Context
A complete astrology engine must generate actionable predictions, executive summaries, strengths, weaknesses, remedies, and formatted reports. Mixing prediction interpretation logic directly into web API routers or astronomical calculation services violates Clean Architecture.

## Decision
We decide to implement:
1. **Decoupled Prediction Architecture**:
   - `PredictionEngine`: Consumes pre-evaluated `RuleResult` entities, `VedicEngine` output, `VargaRegistry` output, and `CalculationContext`. MUST NOT recalculate astronomical longitudes, houses, or vargas.
2. **Multilingual Explanation Engine (`ExplanationEngine`)**:
   - Provides native Tamil explanations first, with English readiness for global applications (`lang="ta"` / `lang="en"`).
3. **Separate Presentation Builder (`ReportBuilder` & `JSONResponseBuilder`)**:
   - Presentation layout and JSON response formatting are completely decoupled from prediction rule evaluation logic.

## Consequences

### Positive
- **Clean Architecture Separation**: Pure separation between calculation pipeline, rule evaluation, prediction synthesis, and report formatting.
- **Multilingual Support**: Flexible localization for Tamil and English.
- **100% Backward Compatibility**: Public router API contracts remain byte-for-byte identical.
